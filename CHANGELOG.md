# Журнал изменений (CHANGELOG)

Все изменения кода и документации фиксируются здесь. Формат основан на
[Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — по
[Semantic Versioning](https://semver.org/lang/ru/). Детали реализации — в
`TECHNICAL.md`; пользовательские инструкции — в `README.md`.

## Типы записей

- **Added** — новая функциональность.
- **Changed** — изменения существующей функциональности.
- **Deprecated** — объявленная устаревшей функциональность.
- **Removed** — удалённая функциональность.
- **Fixed** — исправления ошибок.
- **Security** — исправления уязвимостей.
- **Docs** — изменения документации.

## [1.9.0] - 2026-11-07

### Fixed
- Исправлена замена в полях-списках: в `targets[].rows` уходили объекты строк
  вместо числовых индексов, поэтому `applyListRows` не находил строку и замена
  на странице не применялась. Теперь передаются числовые индексы `li`.

### Added
- Кнопка **«Заменить выбранные»** теперь учитывает и отмеченные строки
  развёрнутых списков: счётчик `(N)` суммирует их с обычными пунктами, а замена
  применяется и к выбранным строкам списка.
- Блок списка **разворачивается** кликом по сводке или «Выбрать для замены»;
  клик по строке списка показывает найденное поле на странице.

### Changed
- Найденные слова на странице и в обычном пункте попапа выделяются **оранжевым**
  (вместо красного).
- Значения, найденные в строках списка, выделяются **фиолетовым** (сводка
  ««<find>» — N строк списка» и сами строки).
- После замены строк списка показывается, на что заменено (**зелёным** жирным).
- `manifest.json` — версия повышена до `1.9.0`.

### Docs
- `README.md` — обновлены цвета подсветки и поведение групповых блоков списка.
- `TECHNICAL.md` — обновлены `MARK_BG`, «Заменить выбранные» с группами,
  разворачивание списка и клик-переход к полю.

## [1.8.0] - 2026-11-07

### Added
- Если в `contenteditable` со списком (`ol`/`ul`) значение найдено минимум в двух
  строках — найденные строки группируются в **один общий блок**: при наведении
  показывается подсказка «Найдено в разных строках одного списка», внутри —
  кнопка **«Выбрать для замены»** (раскрывает построчные чекбоксы) и кнопка
  **«Заменить»**. Если выбор не открывали / ничего не отметили — одна кнопка
  заменяет все строки; после выбора заменяются только отмеченные строки.
- После **отмены замены** значение в списке найденного возвращается к состоянию
  «найдено» (красная подсветка), чекбоксы и кнопки снова активны: `KF_UNDO`
  теперь возвращает индексы восстановленных полей, попап откатывает их
  отображение.

### Changed
- `manifest.json` — версия повышена до `1.8.0`.

### Docs
- `README.md` — описаны группировка строк списка, построчный выбор и возврат
  значений после отмены.
- `TECHNICAL.md` — обновлены групповые результаты (`matchRule`), замена по
  строкам (`targets[].rows`, `applyListRows`/`applyRow`), блок групп в попапе
  и возврат полей в `KF_UNDO`.

## [1.7.0] - 2026-11-07

### Added
- Кнопка **«Заменить все»** — заменяет все найденные значения сразу, без
  выбора пунктов.
- Кнопка **«Отменить»** (`↺`) открывает всплывающее меню с двумя действиями:
  **«Отменить последнюю замену»** (отменяет последний заменённый пункт) и
  **«Отменить всё»** (отменяет все внесённые замены). История отмены — до 100
  снимков полей (`KF_UNDO` с флагом `undoAll`).

### Changed
- Кнопка **«Заменить выбранные»** теперь недоступна, пока не отмечен хотя бы
  один ещё не заменённый пункт.
- Найденные слова выделяются **красным**: на странице (жёлтый фон заменён на
  красный) и в тексте пункта в попапе.
- После любой замены (по пункту, по отмеченным или «Заменить все») заменённое
  значение в попапе выделяется **зелёным жирным**.
- `manifest.json` — версия повышена до `1.7.0`.

### Docs
- `README.md` — описаны «Заменить все», меню отмены, красная подсветка найденного
  и доступность «Заменить выбранные».
- `TECHNICAL.md` — обновлены поток `KF_UNDO`, стек отмены (плоский, `undoLast`/
  `undoAll`), кнопки замены и меню отмены.

## [1.6.0] - 2026-11-07

### Added
- Кнопка-значок **отмены** (`↺`) в подвале попапа: отменяет последнее применённое
  изменение на странице (возвращает предыдущие значения полей, в т.ч. разметку
  `contenteditable`). История — до 20 последних замен (сообщение `KF_UNDO`).
- Чекбокс **«Выбрать все»** над результатами поиска: помечает сразу все найденные
  записи одним кликом; снимается автоматически при снятии любой отметки.

### Changed
- Кнопка **«Заменить»** в футере переименована в **«Заменить выбранные»**
  (с числом отмеченных — «Заменить выбранные (N)»).
- Кнопка **«Очистить все»** теперь полностью очищает область результатов
  (список, отметки и счётчик на кнопке), а не только прячет её.
- `manifest.json` — версия повышена до `1.6.0`.

### Docs
- `README.md` — описаны кнопка отмены, «Выбрать все», переименование кнопки
  замены и очистка результатов.
- `TECHNICAL.md` — добавлены поток `KF_UNDO`, стек отмены
  (`captureField`/`undoLastChange`) и чекбокс «Выбрать все».

## [1.5.0] - 2026-11-03

### Added
- После замены конкретного пункта новое значение в его блоке выделяется
  **зелёным жирным** шрифтом (кнопка «Заменить» у пункта становится неактивной).
- При «Найти» найденные слова **на странице** подсвечиваются жёлтым фоном:
  - в `contenteditable` подсвечивается сам найденный фрагмент текста;
  - в `input`/`textarea`/`select` — всё поле целиком (посимвольная подсветка
    внутри таких контролов невозможна);
  - подсветка снимается при новой «Найти» или любой «Заменить».

### Changed
- `manifest.json` — версия повышена до `1.5.0`.

### Docs
- `README.md` — описаны зелёная подсветка заменённого значения и жёлтая
  подсветка найденного на странице.
- `TECHNICAL.md` — обновлены функции подсветки (`markMatches`, `clearMarks`,
  `wrapRange`) и тест-сценарии.

## [1.4.0] - 2026-11-03

### Added
- У каждого найденного пункта отдельная кнопка **«Заменить»** — применяет правило
  только к этому конкретному полю.
- Множественный выбор для замены: чекбокс у каждого пункта; общая кнопка
  **«Заменить»** внизу применяет замену к отмеченным (если ничего не отмечено —
  ко всем найденным).
- Клик по найденному значению прокручивает страницу к полю и подсвечивает его
  оранжевой рамкой (`KF_SHOW`).
- Найденный фрагмент выделяется жирным и подчёркиванием в тексте пункта.
- Новое сообщение `KF_SHOW` и поддержка `targets` в `KF_REPLACE`.

### Changed
- Замена учитывает регистр написанного в поле слова: `JOHN` → замена прописными,
  `John` → замена с заглавной, `john` → как в правиле.
- Поиск возвращает пункты **по полям** (а не уникальные значения), поэтому каждый
  пункт можно заменить отдельно.
- Индексы полей стабильны между «Найти» и «Заменить»; лимит показанных пунктов —
  50 на правило (далее «...и ещё N»).
- `manifest.json` — версия повышена до `1.4.0`.

### Fixed
- Замена больше не ломает разметку `contenteditable`: подстановка выполняется по
  текстовым узлам, сохраняя списки, жирный текст и стили внутри поля (ранее
  `innerText` сбрасывал их, например нумерованный список превращался в текст).

### Docs
- `README.md` — описан новый процесс замены (по пунктам / по отмеченным),
  подсветка на странице и сохранение регистра.
- `TECHNICAL.md` — обновлены поток данных, структура результата поиска и
  тест-сценарии.

## [1.3.0] - 2026-10-30

### Added
- Кнопка **«Найти»**: показывает по каждому правилу количество совпадений
  с учётом и без учёта регистра, режим (часть значения / полное совпадение)
  и список найденных значений (до 8, с пометкой «...и ещё N»).

  регистр учитывается только при `caseSensitive === true`.
- Попап: вместо единой кнопки «Применить» — раздельный процесс «Найти» →
  «Заменить» с предпросмотром.
- `manifest.json` — версия повышена до `1.3.0`.

### Docs
- `README.md` — описан двухэтапный процесс «Найти/Заменить» и дефолт регистра.
- `TECHNICAL.md` — обновлены поток данных, структура правила, описание
  content script и тесты.

## [1.1.1] - 2026-10-30

### Fixed
- Первое применение на странице, открытой до установки/обновления расширения,
  больше не требует перезагрузки: если content script отсутствует, он внедряется
  на лету через `chrome.scripting.executeScript`, после чего правила применяются
  сразу. Ранее в таких случаях показывалось «Перезагрузи страницу и попробуй
  снова (нет доступа)».

### Changed
- `manifest.json` — добавлено право `scripting`, версия повышена до `1.1.1`.

### Docs
- `README.md` и `TECHNICAL.md` — описан механизм внедрения скрипта на лету,
  убрана необходимость перезагрузки страницы после обновления.

## [1.1.0] - 2026-10-30

### Added
- Признак «Учитывать регистр» для каждого правила: при установленном флаге
  поиск учитывает регистр, при снятом — игнорирует его.
- Поддержка любых `contenteditable`-блоков (ранее только `[contenteditable="true"]`).

  и обновления для Яндекс.Браузера.

  типов, `textarea`, `select`, `contenteditable`, `iframe` того же домена).
- Оптимизация для Яндекс.Браузера: расширение использует только общие
  Chromium API, общие для Chrome и Yandex, и не требует отдельного портирования.
- `manifest.json` — версия повышена до `1.1.0`.

### Docs
